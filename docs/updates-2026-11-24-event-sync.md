## 🔄 듀얼 PvP ↔ 이벤트 서버 동기화 — duel v1.4.16-DUEL · event v1.1.1 (2026-11-24)

- 대상: 스피릿 듀얼(`duel.html`/`duel-core.html`, v1.4.16-DUEL) · 이벤트 웹(`event.html`, v1.1.1)
- 링크: https://kyyj35-wq.github.io/-/duel.html · https://kyyj35-wq.github.io/-/event.html
- 사용자 신고: "이벤트 서버랑 동기화 해 줘, 동기화가 안 돼서 승리해도 안 쌓임"

### 1. 왜 안 쌓였나 (원인)

1. **이벤트 설정을 앱을 열 때 한 번만 읽고 그 값으로 계속 판정했다.** 이벤트가 꺼져 있을 때 게임을 열어 두면, 그 뒤 `event.html` 에서 이벤트를 켜도 이미 열린 화면은 `enabled:false` 인 옛 설정으로 판정해 아무것도 기록하지 않았다(대전 중에 켠 경우 특히).
2. **기록은 이긴 쪽 브라우저에서만 했다.** 이긴 사람 화면이 옛 버전이거나 오프라인·캐시 상태면 그 승리는 어디에도 남지 않았다. 대상자(운영자) 화면이 최신이어도 마찬가지였다.
3. 운영자 화면(`event.html`)은 **새로고침을 눌러야만** 대기 목록이 갱신됐다.

### 2. 고친 내용 (duel v1.4.16)

| 지점 | 바뀐 것 |
|---|---|
| 설정 조회 | 방 만들기·방 참가·대전 시작·**대전 종료**마다 `event_config` 를 `cache:'no-store'` + `?_t=` 로 다시 읽는다. 20초가 지난 설정은 판정에 쓰지 않는다. 같은 순간의 중복 요청은 하나로 합친다 |
| 판정 시점 | `endBattle` 은 결과 창을 먼저 띄우고, **서버 설정을 새로 읽은 뒤** 이벤트 줄(`#evt-result-line`, `aria-live`)만 채운다 |
| 기록 주체 | 이긴 쪽 + **진 쪽(대상자) 화면**. 내 계정이 `hostIds` 에 있고 상대가 로그인 계정이면, 진 쪽 화면이 이긴 상대를 대신 기록한다 → 상대가 옛 버전·오프라인이어도 남는다 |
| 계정 복구 | `B.pvp` 값이 비어 있으면 판정 직전에 `rooms/<코드>_config` → `_host`(방장 핑에 계정 추가) → `_guest`(입장 신호) 순으로 되살린다. 모두 소문자·공백 제거로 맞춘다 |
| 중복 방지 | 항목마다 `key = 방코드|이벤트ID|아이디`. 두 화면이 같은 순간에 올려도 한 건. 올린 뒤 다시 읽어 내 기록을 확인하고, 덮어써졌으면 최대 3번까지 다시 합쳐 올린다 |
| 1인 1회 | 대기 목록뿐 아니라 **지급 기록(`event_claims`)** 도 본다 — 이미 받은 사람은 다시 쌓이지 않는다 |
| 대상자끼리 | 대상자(kyyj35·dev)끼리의 판은 보상 대상이 아니다(운영자 계정이 자기 계정을 이겨 보상을 받는 일 방지) |
| 기타 | `showScreen` 의 `pvp` 분기에서 `renderPvp()` 가 unreachable 이던 버그 수정 |

### 3. event.html (v1.1.1)

- **5초마다 대기 목록 자동 동기화**, 설정·지급 내역은 1분에 한 번 + 창 복귀(`visibilitychange`)·포커스 시 전체 동기화. (무료 네임스페이스 요청 한도를 지키려고 대기 목록만 5초마다 읽는다)
- 입력 중(대기 행 수량·재화 선택, 설정 칸)에는 다시 그리지 않아 타이핑을 지우지 않는다. 저장 전에 고쳐 둔 설정(`eventDirty`)은 서버 값으로 덮어쓰지 않는다.
- 새 기록이 들어오면 `🔔 새 기록 N건이 들어왔습니다.` 를 상태 줄(`aria-live`)에 남긴다.
